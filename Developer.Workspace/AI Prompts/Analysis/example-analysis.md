# Analysis: Example Investigation

## Question

State the question this analysis is intended to answer.

## Background

Describe the relevant system, problem, legacy behaviour, or architectural context.

## Sources to Inspect

Inspect all relevant evidence, including where applicable:

- Current source code.
- Database schema.
- Stored procedures.
- Tests.
- Configuration.
- Legacy implementation.
- Existing documentation.

## Analysis Rules

- Do not modify implementation code.
- Do not assume existing behaviour is correct.
- Distinguish facts from recommendations.
- Identify uncertainty explicitly.
- Call out contradictory evidence.
- Avoid proposing unnecessary abstractions.

## Questions to Answer

1. What exists today?
2. Why does it appear to exist?
3. What depends on it?
4. What problems or risks exist?
5. What should be preserved?
6. What should be replaced?
7. What requires further investigation?

## Deliverable

Produce a concise analysis containing:

- Findings.
- Evidence.
- Dependencies.
- Risks.
- Recommendations.
- Open questions.
- Suggested next step.

Do not implement changes.
